# agentio end-to-end on hardware — 2026-07-26

**Result: PASS.** Every part of the harness worked on the first hardware
attempt. Screen capture, button injection, touch injection and chord typing all
verified on a physical FreeWili 2.

**Setup:** FreeWili 2 (RP2350B) over a Raspberry Pi Debug Probe
(CMSIS-DAP v2, `VID:PID=0x2e8a:0x000c`, serial `E664B4950796592F`, FW 2.0.0,
SWD @ 5000 kHz). Branch `agentio` @ 77d56a3, SDK 2.3.0, toolchain 14_2_Rel1.

## Verified behaviors

- **Capture is faithful.** `shot.png` showed the eight colour bars in the
  expected order (RED GRN BLU YEL CYN MAG WHT BLK) with correct colours, the
  per-bar labels legible, and both text lines — matching exactly what
  `apps/hello_agentio/main.c` draws. This exercises the whole chain at once:
  the ST7796 shadow tap, wire-order byte handling, the PackBits-16 encoder, the
  RTT transport, the Python decoder and the PNG writer. A byte-order error
  anywhere would have produced wrong colours; none appeared.
- **Compression is effective.** A flat UI screen came back as a 2462-byte PNG
  from a 307,200-byte framebuffer, and the capture completed in a few seconds.
- **Button injection reaches the app.** `shot2.png` showed the green swatch at
  x≈48, which is `8 + 20*2` for button index 2 = `UARTKBD_BTN_GREEN` — so the
  injected mask travelled through the synthetic-frame path, the real checksummed
  parser, edge detection, and into the app's event loop.
- **Touch injection reaches the app.** The magenta dot appeared at (240,160),
  the exact injected coordinate.
- **Chord typing works end to end.** `fw type "hello"` produced `hello_` in
  `hello_keyboard`'s text area. Five characters were resolved into press
  sequences on-target against the live keyboard state, queued one edge per loop
  iteration, and typed. The soft-button bar returned to group labels, showing
  every chord completed cleanly rather than leaving a half-entered chord.
- **Crop and downscale work.** Both produced the exact expected dimensions.
- **The error path is fast and clear.** An off-surface crop returned
  `ERR rect` immediately rather than hanging — confirming the fix for the
  whole-branch review's finding 2 (the host previously read 18 header bytes
  unconditionally and blocked for 30 s on any error reply, since every `ERR`
  message is shorter than a header).

## Notes and rough edges

- **Probe contention between one-shot commands is real.** Running
  `fw screenshot` immediately after a previous one-shot command intermittently
  failed with `openocd did not open port 9091 within 10s`, because the prior
  OpenOCD had not finished releasing the probe. A ~2-4 s gap avoids it, and a
  persistent `fw rtt` session (which serves both channels) avoids it entirely.
  Worth documenting for anyone scripting rapid sequences; the diagnostic message
  is at least clear about what happened.
- **Not exercised:** the DVI capture surface. No app in the tree initializes
  both `hstx_dvi` and agentio, so that path remains untested on hardware even
  after this session. The `hstx_dvi_region_base()` fix from the whole-branch
  review is reasoned-correct but unverified.
- **Not exercised:** the two documented failure modes — a capture spinning with
  interrupts masked long enough to disturb IRQ-driven audio, and a host
  disappearing mid-capture wedging the board. Neither was provoked. They remain
  real risks per `docs/drivers/agentio.md`.

## Bottom line

The harness does what it was built for: an agent can now flash an app, drive its
buttons and touchscreen, type text into it, and look at the resulting screen —
with no human at the hardware. That loop is closed.
